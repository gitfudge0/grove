Resizable grids without changing the grid’s identity

Add direct mouse resizing and a short-lived keyboard mode while keeping the existing column-first topology, tile order, focus, and drag-to-reorder behavior intact.

Outcome and definition of done

Outcome

Users can widen or narrow a column, and independently adjust a row split inside each column. Mouse dragging is discoverable through cursors and a compact status hint; keyboard resizing is predictable from the focused tile.

Done when

  • All existing 1–16 tile topologies still render column-first and retain focus/order.
  • Each adjustable divider supports 6px hit zones around a 1px rule, drag, cursor feedback, and double-click reset.
  • mod+r enters a transient mode; arrows or hjkl change the adjacent boundary by 5 percentage points, or 1 with Shift; Enter/Escape exits.
  • Weights clamp against terminal-cell/header/padding minimums, never jump, and reset when column/row counts change.
  • Tests cover geometry, reducer/state transitions, pointer ownership, shortcuts, and manual smoke checks.

Settled interaction proposal

Mouse

  • Render a 1px divider at each column boundary and row boundary; place an invisible DIVIDER_DRAG_HIT_W (6px) zone around it.
  • Use left-right and up-down cursors respectively. Pointer down arms only resize, captures the pointer at the root, and records the boundary’s starting weights and coordinate.
  • Pointer movement converts delta to a percentage-point transfer between the two adjacent regions. Clamp continuously, so the first move cannot jump.
  • Double-click a divider restores that split to equal weights. It does not reset unrelated splits.

Keyboard

  • In Grid screen, mod+r enters transient GridResize mode for the boundary adjacent to the focused tile.
  • Left/right chooses a vertical boundary; up/down chooses a horizontal boundary. h/j/k/l are aliases, following the grid direction convention.
  • Normal step is 5 percentage points; Shift is 1 point. Enter or Escape exits. A statusbar hint shows selected boundary, step, and exit keys.
  • Mouse dragging remains available without entering this mode. Focus and tile order never change.
Pointer ownership is the sharp edge. Existing tile-header drag-to-reorder arms GridDrag, and root mouse-up currently commits/releases it. Add distinct GridPointerDrag::Reorder(GridDrag) and GridPointerDrag::Resize(GridResizeDrag) variants (or equivalent tagged enum) so a divider gesture cannot also be armed as reorder. Root move/up must match on the variant and clear exactly one owner.

Double-click branches from any divider to reset its pair. Enter/Escape branches from GridResize mode to Grid idle. Reorder follows its existing, separate pointer variant.

Minimums and clamping. Derive each tile’s minimum width/height from terminal cell metrics plus existing header height and PTY padding. If metrics are unavailable at calculation time, use a conservative logical-pixel floor. Convert the minimum into a minimum weight for each pair, clamp the receiving and donating side together, and retain the original pointer baseline so dragging against a clamp does not accumulate error or jump when it resumes.

Manual verification, rollout, and non-goals

Manual pass

  1. Open 2, 3, and 4 session grids; drag every vertical and applicable horizontal seam.
  2. Confirm cursors, 1px visual rule, 6px forgiving hit target, and no reorder on resize.
  3. Try clamp edges at narrow and zoomed windows; reverse direction without a jump.
  4. Focus each tile, enter mod+r, exercise arrows/hjkl, Shift, Enter, and Escape; verify status hint.
  5. Double-click one split and confirm only that split resets; add/remove a tile and confirm all sizing resets.
  6. Switch light/dark themes and verify seams, hint, and focus affordances remain legible.

Rollout

Ship behind a grid-resize feature flag if the project’s existing flag pattern supports it; otherwise the behavior can be enabled as a contained grid-only change. Instrument no new ordering/persistence event unless product asks for it.

Non-goals

  • No freeform tile placement, spanning, or topology editing.
  • No resizing in single-session/non-grid layouts.
  • No persistence, sync, import/export, or per-project profiles in v1.
  • No change to keyboard move/swap semantics or terminal content behavior.
Risk to watch: root mouse-up ownership and header reorder are more dangerous than the math. Land the tagged pointer state and event tests before enabling visual handles.

Open question

Should v1 persist sizing? Recommended: session-only. Reset weights whenever column/row counts change, and revisit persistence after observing whether users expect layouts to follow a workspace or a topology.
