One flat dispatch chain is the root of the bug cluster. This is the plan to make every key resolve against its screen — and fall through cleanly when it doesn't apply.

Diagnosis

There is no per-screen key handling

Every key funnels through one 80-line handle_key with a 7-guard chain. Screens only change which PTY the fallthrough writes to — never whether a shortcut applies.

What exists ✓

Screen enum (Grid/Workspace/Zen), Scope enum, a SHORTCUTS registry where each row declares its scopes, and current_screen().

What's missing ✗

match_global_shortcut never reads scopes. Only view.rs reads it — to draw the overlay. Scope is decoration, not enforcement.

So the whole class of bugs is one missing wire: the matcher ignores the screen.

This is the load-bearing insight. The team already built the scoping vocabulary in commit 8d6968c but only used it for display. The plan is mostly "finish wiring what you already designed."

The design

One context in, one decision out

Compute the active input context once, then resolve every key against it. Out-of-scope keys aren't consumed — they fall through to the PTY.

1
Modal / captured → handle_modal_key (unchanged path, fixed in phase 3)
2
Grid (tile focused?) → grid-scoped shortcuts, else forward to focused tile
3
Zen → global shortcuts only, else forward to active session
4
Workspace (+ panel focus) → global + workspace shortcuts, else forward

The invariant: a shortcut consumes a key only if its scope contains the current screen. No match ⇒ fall through. That single rule is the fix.

Key mental model shift: today the chain asks "is this a known chord?" It should ask "is this a known chord that applies HERE?" The difference is bug 1 and 2.

Phase 1 · biggest bang, smallest change

Make scope authoritative

src/gui/update.rs · match_global_shortcut
fn match_global_shortcut(key, mods, screen) -> Option<GlobalShortcut> { // ... find the def by trigger + modifiers ... + // enforce scope: a def only matches on its declared screens + if !def.scopes.iter().any(|s| s.matches(screen)) { + return None; // out of scope -> caller falls through to PTY + } def.action }

Fixes 1

mod+w outside grid returns None → falls through instead of dead no-op.

Fixes 2

Move term-panel resize into the registry, scoped to Workspace + cfg(macos) mod. No more invisible-panel resize.

This phase is small and self-contained. current_screen() already exists so the plumbing is a one-arg thread-through. Do this first — it's the highest-value, lowest-risk change and validates the whole model.

Phase 2 · single source of truth

Compute context, don't re-derive it

Today the dispatch reads term_panel_open, grid_view, chrome_visible in scattered guards. Collapse them into one function.

src/gui/update.rs
enum InputContext {
    Modal { captured: bool },
    Grid  { tile_focused: bool },
    Zen,
    Workspace { pty: PtyTarget },   // Agent | Panel | Home
}

fn input_context(&self) -> InputContext { /* the ONLY place flags are read */ }

Dispatch becomes a match on the context. Every "which screen am I on" question has exactly one answer, computed once per key.

This is the refactor that makes the invariant enforceable. It also naturally documents the PTY routing priority (grid tile > home terminal > panel > agent) that today is buried in focused_session_mut.

Phase 3 · the modal / Escape layer

Stop losing the first Escape

The trap

iced's text_input returns Status::Captured for Escape (it just blurs itself). The subscription drops captured events, so the app never sees the first Escape.

The carve-out

In the subscription, forward Escape even when captured — its only in-field effect is a harmless self-blur:

if status == Captured && key != Escape { return None }

Same phase: fix bug 4 (launcher missing text_input::focus) and bug 6 (onboarding Tab always targets the wrong field; name field has no .id()).

The Escape carve-out is the one genuinely iced-specific fix. It's surgical: only Escape bypasses the Captured filter, so we don't reintroduce double-handling of typed text. Verified against iced_widget 0.13.4 text_input.rs:1083.

Phase 5 · registry hygiene & docs

Close the gaps that let it rot

Bug 7 · dead row

NewSession and NewSessionInWorktree share triggers ["n","N"]; the .find() never checks requires_alt, so the second row is unreachable — only a special-case ahead of the lookup saves it. Reorder the rows and mod+n silently breaks.

Fix: make the lookup match on requires_alt too; delete the special case.

Bug 11 · doc drift

mod+alt+n, mod+w, Ctrl+Shift+←/→ work but are documented nowhere / in no overlay.

Fix: generate the README table from the SHORTCUTS registry so prose can't drift from code.

Making docs a projection of the registry is the durable fix — same as making the overlay a projection. Once behavior, overlay, and docs all read one array, they can't disagree.

Each phase is independently shippable and testable. Phase 1 alone changes how the app feels.

Deliberately front-loaded: the highest-value, lowest-risk change goes first and de-risks the model before the bigger refactor. Nothing here is a big-bang rewrite.
