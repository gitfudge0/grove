# Grove design system contract

This is the normative UI contract for Grove’s native Rust/GPUI app. It records approved hierarchy, component roles, interaction states, and exceptions. The executable source owns exact values: [tokens](src/views/tokens.rs), [semantic colors](src/theme.rs), [shared controls](src/views/components.rs), [icons](src/icons.rs), and [motion](src/views/motion.rs). These are requirements, not claims that every runtime state has been verified. Use source inspection and native checks to assess implementation; report any mismatch. Latest explicit user direction takes precedence; reconcile the contract in the same change.

Use the [project UI skill](.agents/skills/grove-ui/SKILL.md) for implementation and verification. Codex and Claude share that procedure. Historical CSS migration tables and proposed APIs are [archived](docs/design/2026-10-22-migration-catalog.md); neither that archive nor `DESIGN.html` defines current values or implies unfinished migration work.

## Foundations

- One app-level theme setting chooses from a single list of standalone light and dark themes. Workspace and project views never override it. Grove Light and Grove Dark preserve the established appearance; legacy System/Dark/Light settings migrate to matching Grove defaults, with explicit saved theme identity taking precedence. Main canvas, sidebar and appbar/statusbar strips are opaque. Native editors, Markdown, diffs, selection, terminal ANSI/default colors, and integrated HTML reports follow the same resolved theme generation. Explicit terminal RGB colors and intrinsic assets retain their authored colors. Ordinary authored HTML retains its own styling.

- Use semantic `c::*()` colors, not copied hex values or a PTY palette for app chrome. Neutral fills express hover, selection, focus, and open state. Violet is reserved for agent identity, connection, and active-port roles; green means success, amber needs-you/warning, red error/destruction/interruption, and blue information or the explicit activity/effort roles below. Pair status colors with meaningful glyphs or text. On light surfaces, supporting status indicators accompany legible foreground copy; destructive copy uses the semantic error role.

- Status displays outside conversation transcript content use the shared semantic presentation: a plain catalog mark with a matching semantic-color label, without a colored pill or backplate. Working uses a blue open ring (static with Reduce motion), success a green circle-check, needs-input an amber circle-dot, warning an amber circle-exclamation, and failed a red circle-cross. Idle, pending, unknown, canceled and stopped use distinct quiet neutral marks. Compact contexts may omit the visible label while preserving accessible meaning and the shared mark. Domain owners map their actual state explicitly; literal provider diagnostics, task progress, Git counts and actionable control semantics remain intact. Long diagnostic labels wrap beside a fixed leading icon slot.

- Claude and Codex provider logos retain their brand colors in every placement, including compact status overlays: Claude uses its authored orange; the OpenAI Blossom used for Codex is black on light themes and white on dark themes. Provider marks never inherit status, selection, or muted text tints. Adjacent text and separate status marks retain their semantic roles.

- DM Sans (`UI_FAMILY`) is the application UI family for labels, forms, paths, branches, metadata, keycaps, native diffs, and script editors. JetBrains Mono (`MONO_FAMILY`) is the monospace family for terminals and Markdown code; preserve terminal cell metrics. Every application surface, vendor control, diagram, and embedded HTML document uses these two configured families. Embedded HTML retains monospace semantics while authored font choices are normalized. Platform glyph fallback remains available for characters absent from the bundled fonts. Use semantic type roles from tokens, explicit line height where needed, and normal tracking. Display type belongs to sparse empty states/onboarding, never chrome.

- Numeric geometry uses existing tokens via `rpx()` and scales once with app rem zoom. Hairlines remain unscaled logical pixels. `icon()` applies scaling itself; never scale its size twice. Shadows needing pixels convert rem-scaled geometry with the current rem size. A one-consumer dimension is a named module constant, not a new global scale tier. First fit the existing component recipe; a new shared token requires a repeated semantic need and approved direction.

- Fields/cards are flat, without bevels or inset shadows. Surface steps and neutral seams establish hierarchy; floating menus, tooltips, and panels use their shared recipes. Grid tiles meet flush with subtle seams, including the top edge, without item gaps or heavy tile borders.

## Controls, forms, and states

| Need | Shared recipe | Contract |
|---|---|---|
| Header/icon action | `header_control`, `header_control_with_tooltip` | Stable icon slot, accessible name, shared tooltip and geometry; owner supplies missing focus/activation behavior. |
| Full form field | `form_field` | Embedded supporting label above a DM Sans value in a filled well; semantic error attached below. |
| Project flow field | `project_form_field`, `project_field_well` | Match the existing project canvas recipe; editable and readonly values share the well. |
| Action button | `form_action`, `transcript_action`, `dense_action_with_colors` | One size: the complete smaller dense recipe, including label, glyph, gap, padding, radius, and vendor inner size tier. Semantic colors may differ; form actions do not grow. |
| Questions/settings | `question_choice`, `question_disclosure`, `settings_control` | Neutral selection/open treatment with component-owned keyboard focus; owner supplies interaction semantics. |
| Preferences/readonly/errors | `boolean_choices`, `readonly_value`, `attached_validation` | Owner supplies accessible role/input; readonly content remains literal and selectable; validation joins its field in normal flow. |
| Task/status content | `task_mark`, `task_meter`, shared status primitives | Reuse the same semantic status and progress representation across owning views. |

Enabled buttons use a pointer cursor across their entire hit target, including padding, icons, labels, and nested content. Disabled and loading buttons use the default arrow and reject activation. This includes custom action rows, disclosures, grouped preferences, selectors, and app-owned HTML actions; editable/selectable text and resize handles retain their purpose-specific cursors. Ordinary authored HTML retains its own styling.

A shared visual helper does not necessarily supply a complete interactive control. Where the helper does not provide them, the owner supplies a stable ID, focus/tab behavior, keyboard activation, action handling, and enabled/disabled semantics.

Full form geometry uses `FIELD_H`, `FIELD_INSET_X`, `FORM_VALUE_SIZE`, `FORM_VALUE_LINE_H`, and `TEXTAREA_H`. Form fields use `RADIUS_PANEL`; grouped preferences use `RADIUS_PREFERENCE`; action buttons use `CONTROL_H` and `RADIUS_CONTROL`, except the taller start-list rows below; compact menus use `RADIUS_CHROME`. Labels use supporting text contrast, not quiet metadata contrast. Split fields represent semantic pairs. Textareas grow vertically. Disabled opacity does not itself disable input: disabled controls must reject interaction while enabled and readonly labels retain normal contrast.

The main-content checkout/worktree start list uses full-width, left-aligned launch rows with transparent rest backgrounds and horizontal seams at the top and below every row, without an enclosing filled or rounded card. Row height and larger decorative provider glyph size are owned by local `PROJECT_START_ROW_H` and `PROJECT_START_ICON_SIZE` constants. The shared dense action recipe retains its typography, padding, neutral hover/press treatment, keyboard activation, and accessible name. Each provider glyph precedes its truncating provider name with `SPACE_SM`; a fixed quiet trailing arrow indicates the launch destination and is not a separate action. All providers receive equal weight.

Focus and open states on inputs and dropdowns use neutral fill changes and stable borders. Never add white or foreground-colored borders/outlines to these controls. Preserve visible carets, labels, validation error borders, keyboard navigation, and accessible names. Keep hover, keyboard `focus_visible`, selected rows, and intentionally open state distinct. Action buttons return to rest after release; clicking must not leave a persistent highlight. Other controls retain appropriate keyboard focus indication without shifting geometry.

Text-and-icon buttons always place their catalog icon before the label, separated by the shared dense gap (`SPACE_SM` via `rpx()`). Directional action icons follow the same rule. The checkout/worktree start list additionally reserves a quiet trailing destination arrow after the provider name; its larger leading provider glyph remains the action identity. Trailing field indicators and metadata on non-button controls retain their positions. Loading replaces/animates the leading icon without changing its slot; disabled actions keep it. Icon-only actions have an accessible name and tooltip; visible text supplies the name when present and decorative glyphs stay hidden from accessibility. Grouped preferences/selection controls express state directly and need no decorative action icon. Use the catalog meaning (plus add, check confirm/save, close cancel, trash delete, refresh retry, folder/list/grid destinations, more manage, chevrons disclosure), never text characters as substitute icons, decorative wrapper boxes, violet backplates, or stretched glyphs. Clickable chrome glyphs do not exceed `ICON_LG`; `ICON_20` is the decorative command-palette exception, checkout/worktree launch rows use their local decorative provider glyph size, and display glyphs remain decorative.

Use the shared inverse tooltip surface in both appearances. It wraps long names, scales with rem zoom, and preserves component-owned timing/placement. A tooltip does not replace the trigger’s accessible name or full identity.

## Alignment and responsive layout

Bottom form actions share one horizontal, left-aligned wrapping row at the same column inset as the form content. Cancel and primary actions stay together; do not spread them across the footer.

Reserve leading icon, label, metadata, and trailing action/count space appropriate to the row. Truncating text yields before fixed controls. Revealing close, Copy, or task actions preserves the row’s geometry; loading feedback retains its icon slot. Worktree launchers intentionally replace Git counts on hover/focus and may occupy a different trailing width. Do not let a flex label consume the space required by a trailing control. Header height follows its remaining content when controls move elsewhere. Project navigation headings reserve count and action widths before shrinking their title; at widths that cannot fit both groups, actions wrap into a transparent following row without overlap or hidden controls. Test long labels and narrow widths; avoid clipping and overlap rather than hiding meaningful actions.

## Overlays, keyboard, and motion

Blocking confirmation stays attached to the row, tile, switcher, or manager action that opened it. A low-opacity neutral veil makes the app inert while preserving a crisp source aperture. The tray shares the source edge, uses one neutral seam, and presents consequences inline. It is never a centered modal, blurred/blackout overlay, colored edge, or separated header/footer bands. Workspace creation morphs in an anchored switcher popover without moving; deletion expands in place. Escape/Cancel preserves state and returns focus to the source. Deferred/anchored paint order is not a CSS z-index API: verify hit testing, input ownership, outside dismissal, and focus separately.

Use shared fast/base/slow motion and stable keys tied to meaningful state changes, not every render. Command palette and child activity previews animate both entrance and dismissal; previews use shared fast motion and the palette retains base motion; exiting content releases keyboard ownership immediately, and reopening cancels stale dismissal. Child preview headers lead with a small supporting line containing the brand-colored provider glyph and available agent role, followed closely by the worker name and its compact, vertically centered status at their existing size. Provider identity remains available in the accessible preview name without repeating visible provider text. With Reduce motion enabled, native chrome renders immediate endpoints/static activity without creating animation state or scheduling animation frames. Embedded HTML receives the preference: suppress CSS animations/transitions, cancel active Web Animations, and notify scripts through the preference event and `matchMedia`. Authored scripts must honor the preference; this integration does not stop arbitrary JavaScript timers or animation-frame callbacks. Keep focus, keyboard actions, PTY output, layout, and resizing immediate. The effort slider below is the explicit pointer-motion exception and still honors reduced motion.

Shortcut numbers, clean placeholders and elapsed age are not visible; the accessible name and tooltip preserve full context, status age, provider, tasks and shortcut. Git counts align to the visible status-glyph edge within that trailing slot. Worktrees and their session identity retain the intentional nested hierarchy.

Expanded, its workspace selector, Settings and Collapse share the window-control row. The shared header retains its usable row height beneath a rem-scaled top inset; adjoining chrome, content headers and anchored overlays use its full extent. Fullscreen hides every custom window control and removes their reserved footprint, allowing workspace identity to lead at the left inset. Launch and daily polling refresh eligibility without interrupting installation or a pending restart. Workspace identity yields to fixed actions, and Collapse sits directly after Settings; collapsed, that header contains only Expand. Workspace switching and current-view controls lead the compact scroll region, followed by project/session navigation and a separate standalone-terminal group.

Settings and Add project form the bottom utility group; Archived projects is reached from Settings > General. Add terminal stays with standalone terminals. These groups share one scroll region under the fixed header. Compact tiles use contextual hover tooltips, accessible names, and keyboard focus; keyboard access must not depend on a tooltip appearing. Collapse persists independently of the remembered expanded width. Custom macOS window buttons hide in fullscreen and while the compact navigation rail is visible, and Grid and Zen retain their existing layouts. Compact session and standalone-terminal tiles center the 16px identity glyph on the rail. Status overlays its lower-right corner: a 10px glyph within 12px circular clearance, positioned at the tile center (18px from the left, 16px from the top of the 36 × 32px tile). Clearance reveals the actual rail or interaction fill. Status remains decorative within the session target; Close retains its upper-right slot.

The sidebar currently omits the cross-project session section, including its empty launcher, in expanded and compact navigation. Existing cross-project sessions and launcher access remain available through the app's other session views and commands. Section headers use small sentence-case type and align with session card left edges.

## Workspace and checkout flows

### Workspace controls and input copy

Dropdown triggers and menu items use neutral hover/selected fills for clicked, open, and focused states, with stable borders and no white or foreground-colored outline. Preserve keyboard navigation and accessible names. Other controls retain their keyboard focus rings.

Workspace menu rows are 28px high, with 8px horizontal padding and icon-to-label gap, 6px menu padding, zero adjacent item gap, and 4px vertical separator margins. Create workspace uses the plus icon; Manage workspaces uses the more icon. Pinned actions use the same row spacing. Workspace management offers rename and deletion, without workspace ordering controls. Moving projects between workspaces is a separate operation.

Project overflow menus offer “Move to workspace…” beside Edit project. The project panel shows the current workspace and existing destination workspaces with a clear selected state, then an explicit “Move project” action. The folder and worktrees stay in place and open sessions keep running. Cancel or Escape preserves membership and restores source focus. If no other workspace exists, explain that a destination must be created and disable submission. Errors remain inline for retry.

The “Open destination workspace after moving” Off/On group starts off for each move. Successful moves close the panel and confirm the named destination in the status message. With Off selected, Grove keeps the current workspace active and clears stale source selection; with On selected, membership and active workspace persist together, then Grove opens the destination and selects the moved project.

Placeholders show meaningful example values and never repeat the label or title: Workspace uses `e.g. Platform`. Destructive confirmation starts empty, with the exact target workspace name as its placeholder; enable deletion only after the user types the matching name.

They expose author email/exact time, complete literal multiline message, local branch/tag/HEAD and cached remote-tracking context, and committer attribution when it differs. File rows name change status and rename source/destination; truncated identities remain readable in the selected file detail. File counts and line totals accompany explicit parent comparison semantics.

Bounded pages offer older commits up to the stated limit, with honest continuing parent paths. Root changes compare with the empty tree; merge changes explicitly compare with the first parent. Empty, rename-only, binary and oversized diffs retain their distinct meaning. Cached remote-tracking decorations describe the local snapshot; no fetch, Git mutation or remote graph is implied.

Additional Review PR and detected-failure Fix failed CI actions submit into the current native chat beside the checks. A compact semantic readiness summary remains visible; individual merge-gate reasons belong inside the existing expanded checks/reviews disclosure. Metadata, readiness and expanded details align with the title, leaving the icon column empty.

GitHub CLI, authentication and network failures remain distinct from no existing PR.

Agent rows follow the Changes divider when the session has observed agents. A smaller muted second line shows the current observed process or activity, falling back to the assigned task when activity is unavailable; completed activity does not claim a successful outcome. Reserve one supporting line for stable updates, truncate long visible text, and use tight vertical spacing between agent rows rather than nested cards. Omit repeated unavailable placeholders. Full available task/activity and provider/status identity remain in the accessible name and native activity preview. Agent rows use a neutral hover fill. The preview exposes task, role, status and provider, and renders all available child messages and tool calls chronologically through the main transcript renderer, including Markdown, tool disclosures, outputs, failures and the main transcript’s original active shimmer. ### Composer model, effort and speed

The existing card adds a separated Speed row with neutral grouped Standard/Fast choices and Codex Ultrafast, a Next turn hint, and visible cost and unavailable explanations. Speed is a saved conversation preference independent of reasoning effort and access. New sessions explicitly start Standard; older conversations retain inherited speed until explicitly selected. Model switches never silently change the saved speed or select a different model to enable Fast. If a model cannot use the requested speed, explain that Grove requests Standard while retaining the preference. Only advertised provider/model capabilities enable paid choices; provider account/organization restrictions and literal errors remain authoritative. Claude offers no Ultrafast. The toolbar shows the chosen preference, not an assertion of provider acceptance. Actual provider reports are distinguished from requested speed; an absent effective tier must never invent a fallback. Changing speed applies at the next turn without altering the active turn, queued prompts, drafts, images, references or session ownership. Speed choices support keyboard focus and Enter/Space; disabled choices explain their reason.

The combined model · effort · speed toolbar control opens a compact rounded card directly above its trigger with a SPACE_LG gap. Access remains a separate control.
