Base branch selection — Flows & States

Design review mock for letting the user choose the base branch when creating a worktree. Currently git worktree add -b <name> <dest> runs with no start-point, so the base is silently whatever HEAD the project root happens to be on. Four interaction variants are compared in Section B; Variant A is carried through the lifecycle and edge-case sections as the recommended baseline.

Core gap: there is currently NO branch enumeration anywhere in grove-core — no git branch --list, no for-each-ref, no ls-remote. A branch picker needs new core plumbing built before any variant below can be wired up.
Modal plumbing: Modal::Input today is backed by a single String buffer. Adding a base-branch field makes this the app's first multi-field modal — real implementation cost, not a trivial UI tweak.
B Variants — four interaction approaches to the same target state
Prefill rule (applies to all variants): the base field is always prefilled with a sensible default (repo's default branch, or current HEAD). Choosing a base must never become a mandatory extra step — one Enter keypress still creates a worktree in the common case.
B1Variant A — inline row, collapsed

Same 480px modal. Body becomes a 2-row settings_card_block: Name, then Base showing the prefilled branch + chevron.

Tradeoff: minimal build cost, smallest change from today — doesn't scale to huge branch lists.
