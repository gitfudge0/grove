Decide

Six role-specific voices were given the same grounded brief — the real code: grid_view: bool at workspace_state.rs:326, the 36px PROJECTS header that already carries two icon buttons, the 3-state collapse ring whose middle stop is literally SessionsOnly, and the three existing session-creation entry points that all funnel into Sidebar::spawn_session_in.

Each answered alone, with no sight of the others. Where they converged without coordination is treated as the strongest signal in the room.

RECOMMENDATION

Build it as a rail content mode, not a third top-level view. Ship option C — and pay for it by deleting SessionsOnly.

Add one icon to the PROJECTS header that swaps the rail’s contents between the project tree and a flat, cross-project session card list, sorted attention-first. The body and terminal never move. Introduce RailMode { Tree, Sessions } local to the sidebar entity — not a third state on grid_view, which stays a bool. Simultaneously collapse the tree-cycle ring from Collapsed → SessionsOnly → All back to two stops, because the new mode does that job properly. Net user-visible modes: unchanged. The + goes at the bottom of the card list and opens the existing launcher palette — a fourth doorway to the same funnel, not a fourth funnel.

Why

  • The real unmet need every voice named independently is cross-project attention triage, not “a new view”. The tree buries that under project nodes; a flat list surfaces it.
  • C is the only option that keeps the terminal on screen while you scan — the daily-driver’s single hardest requirement.
  • Zero new tokens, zero new components: card(), RowDensity::Card and palette_row already exist. Conformance R1–R8 passes untouched.
  • Retiring SessionsOnly means the feature reduces the surface it lands in rather than adding to it.

Risks to watch

  • 220px. SIDEBAR_MIN_W is 220 — a two-line card with label, branch, project and status has to degrade legibly, not clip. Prove this before anything else.
  • Density collapse at N=40. Cards are ~54px vs the tree’s 28px row. Forty sessions is a 2,160px scroll. Attention-first sort is what makes that survivable; without it the list is worse than the tree.
  • Two rail modes means a persisted preference, a restore path, and a keybinding — small, but it is real state that must round-trip.
  • The + risks reading as “new session here” with no worktree context. It must open the launcher, never silently spawn.

Conditions

  • Card must render acceptably at 220px before implementation is approved.
  • Sort order is fixed and non-configurable: needs-you → working → idle → done. No user sort in v1.
  • Ship the SessionsOnly removal in the same change, not “later”.
  • Reuse TileData’s shape for the card view model rather than minting a third session view model.
  • Toggle icon must be a distinct glyph from the existing plus and cycle buttons — three icons in a 36px header is the ceiling.

Out of scope

  • Any change to grid_view, the grid tiles, or zen mode.
  • A third value on the view enum; telemetry’s two-bool screen derivation stays as-is.
  • Session grouping, filtering, search, or pinning in the card list.
  • Making the card list the default rail mode on first launch.
  • Bulk actions (kill-all, multi-select) on cards.

The room, independently

Six reads, each written without sight of the others.

Priya Raghavan
Product — owns what ships
Solve the stated problem, not the requested feature
Conditional

Take

The ask is phrased as a view but the pain is a query: “which of my running agents is blocked on me right now, across all projects.” Nothing in Grove answers that in one glance — the tree answers “what projects do I have”, the grid answers “show me everything at once”, and the launcher answers “start something new”. Build the answer to the actual question and the view falls out of it. If we build the view first we’ll ship a prettier tree.

Flags

If the card list isn’t sorted attention-first it has no reason to exist — it’s the tree with more whitespace. Sort order is the feature; the cards are packaging.

Tomás Lindqvist
UX / information architecture
Mode legibility & scan cost
Skeptical of A

Take

Grove has two top-level modes today and a user can always tell which one they’re in because one has a sidebar and one doesn’t. A third breaks that: “sidebar replaced by cards” and “full-screen grid of cards” look like the same thing at a glance and behave differently. That’s the worst kind of mode — visually near-identical, functionally distinct. Also: a card list is slower to scan than a 28px row list once you pass roughly a dozen items, because scanning is driven by items-per-viewport, not per-item prettiness. Cards win only if each card carries information the row genuinely can’t.

Flags

At 40 sessions the card list is strictly worse than the tree unless sort does the work. Define the N where it stops helping and say out loud that we accept it.

Wren Okafor
gpui / Rust — owns workspace.rs
Keep shell state representable
Skeptical

Take

There is no screen enum today — there’s grid_view: bool plus grid_view_before_zen and grid_view_before_terminal, and telemetry reconstructs a screen name from two bools at workspace_state.rs:503. Widening that bool to a three-state enum forces every “remember what it was before” shadow field to widen with it, and every restore path becomes a 3×3 matrix I have to hand-verify. The render switch at workspace.rs:2547 is currently three branches; option A makes it five with two that differ only in what fills the rail. Sidebar-local state costs me nothing — the sidebar entity already owns its own collapse ring.

Flags

Whatever we choose, the mode must survive zen-mode round-tripping. That’s where the existing before-zen fields came from, and it’s the bug we’ll ship if we’re careless.

Dana Ibarra
Design system + conformance suite
No new tokens, no forked shapes
Conditional

Take

A session card is already buildable today with nothing new: components.rs:819 card() gives rounded-4 / BG_STRIP / 1px BORDER with a full-bleed divider, RowDensity::Card gives the row rhythm, and palette_row’s fixed 54px two-line shape with a 24px icon slot is almost literally the requested card. If a proposal needs a new token to look right, DESIGN.md §13 says the proposal is wrong — and I’d hold that line here. My condition is layout, not looks: the card has to hold at SIDEBAR_MIN_W 220, and nothing in it may reflow on hover or use colour as the only carrier of status.

Flags

A third view model for the same session data would be the real debt. There are already two (SessionHeaderData, TileData). Derive from TileData or we’ll have three places to fix the next time status semantics change.

i
Stance pills. For — would ship this as asked. Conditional — supports it if a named condition holds. Skeptical — argues against the shape as proposed, not necessarily against the goal. Stances are independent reads, not votes; the recommendation weighs them, it doesn’t count them.
Marco Feld
Daily driver — runs 8–15 agents at once
Never lose sight of the terminal
For — as C

Take

What I actually do all day: an agent pings, I scan for the “needs you” bar, I jump, I answer, I go back to whatever I was reading in the other session. Options A and B both take the terminal off screen to do that — which means the scan costs me my place. The thing I want is a rail I can flip into “just the sessions, all projects, blocked ones on top”, while the terminal I’m mid-thought in stays right where it is. The plus is nice but honestly I never struggle to start a session; there are already three ways and I use two of them.

Flags

If flipping the rail resets scroll position, or loses which session is focused, I will stop using it within a day.

Nadia Behrens
Release & telemetry — eats the consequences
Surface area we can still reason about
Skeptical

Take

Count what exists before adding: three top-level shell states, a 3-state collapse ring, a grid, a launcher palette, and three session-creation paths. The proposal adds a fourth session surface and a fourth creation path to a tool used by one person. Every one of those is a state combination someone has to hold in their head when a bug report says “the sidebar was empty”. I’ll support this only if it is net-neutral or negative on modes — and there is an obvious donor: SessionsOnly in the collapse ring is a half-built version of exactly this feature. Build the good one, delete the bad one.

Flags

Telemetry derives the screen name from two bools. Any mode we add that isn’t reflected there becomes invisible in usage data — meaning we’ll never learn whether this was worth building.

Unprompted convergence

Three voices who never saw each other’s input — Priya (product), Tomás (UX) and Marco (daily driver) — independently landed on the same thing: the value is in the ordering, not the card. Attention-first sort across projects is the feature; cards are the container it arrives in. Separately, Wren and Nadia independently rejected widening grid_view, from opposite directions — one on restore-path combinatorics, one on debuggable surface area. Both convergences are treated as load-bearing in the recommendation above.
