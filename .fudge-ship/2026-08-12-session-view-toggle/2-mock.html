K Scope & data notes
Deliberately NOT shown — out of scope per the decision.
  • No changes to grid or zen views. The toggle is rail-local and does not exist in the appbar.
  • No grouping, no filter, no search, no pinning in the card list. Sort order is the only organisation.
  • No bulk actions — no multi-select, no "kill all", no checkboxes.
  • Cards are not the default mode on first launch: the rail opens on the project tree, exactly as today. Mode is remembered per run only after the user flips it.
  • No drag-to-reorder, no card resize, no per-card settings surface beyond the existing more menu.
Data model: every element maps to existing TileData.
  • agent glyph → icon_name · label → agent_label
  • project line → project + branch
  • context line → context
  • needs-you → waiting · working → running · selection ring → focused · D6 → confirming_kill
Gaps to resolve before build:
  • done vs idle vs exited are three distinct card states (D3/D4/D5) but TileData only carries the booleans waiting/running. Either widen it to hold the ActivityState enum, or accept collapsing D3/D4/D5 into one "not running" state. Recommendation: carry the enum — it is already computed upstream, and the sort bands need it anyway.
  • The header count badge (G1, H1) is a derived len(), not a field — free.
  • Nothing on the card uses spawned_at, wt_path, tmux or tmux_name. Relative age was drawn and cut: at 320px it competed with the context line, which is strictly more informative.
Conformance self-check (R1–R8).
  • R1 tokens — card 4 / list gap 6 / list pad 8 / row px 10 / min-h 38 / bar 3 / glyph 14 / status col 15 / btn 24 & 28 — all named tokens.
  • R2 borders — 1px only. BORDER on the card and rail edges, BORDER_SOFT for the intra-card divider and button rings.
  • R3 no reflow — the more button holds its 24px slot at rest; hover only paints. Arming (D6) changes fill and words, never geometry. The disabled header button (H1) drops its ring, never its box, and never uses opacity.
  • R4 colour never alone — dot fill-vs-hollow, spinner, close mark, the status word and the pulse each independently encode the state.
  • R5 motion — spinner, attention pulse, caret blink. Nothing else moves; the list does not animate on re-sort.
  • R6–R8 — no new component, no new sprite, no new tier: card(), Card rows, icon_btn, keycap, status_dot, palette_row are all reused as-is.
