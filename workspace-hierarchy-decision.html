Six independent perspectives evaluated the proposed hierarchy against Grove's session-first job: managing git worktrees and persistent AI agent PTYs without turning the app into a dashboard.

Recommendation

Adopt Workspace → Project → Worktree → Session as the domain model, but do not render it as a four-level tree by default.

Auto-create a default workspace so onboarding begins with Add project, not Create workspace. Add a persistent leftmost Workspace rail. It stays visually quiet with one workspace and becomes more useful as workspaces grow. Keep all live sessions globally reachable. Use two primary destinations: Monitor and Project. Monitor owns List/Grid as layout toggles over the same session collection. Project owns project/worktree organization and contextual session creation.

Why

Workspace is useful for cross-project grouping. Users work mainly with sessions and worktrees. Separating destination from layout prevents mode confusion and keeps urgent sessions visible.

Risks to watch

  • Workspace vocabulary collision
  • 52px horizontal cost and icon recognition
  • Global vs workspace filters
  • Hidden recovered sessions
  • State migration complexity
  • Ambiguous current project

Conditions

  • Stable workspace_id, project_id, and worktree identity
  • One-way config migration
  • Versioned tmux metadata
  • Explicit recovered sessions group
  • Define workspace capability beyond grouping
  • Accessible names, keyboard traversal, focus order, and overflow behavior
  • Validate with 5 to 15-session users

Out of scope

Collaboration, team sharing, cloud sync, permissions, workflow graphs, task tracking, and replacing Git concepts.

01

Recommended information architecture

Organization and navigation are related, not identical.

Layer 1 · Workspace rail

A persistent 52px leftmost rail, within a 48 to 56px range. Stack workspace monograms vertically. The active workspace uses fill plus outline or a side marker. Show a compact needs-you dot and count, a plus action, and Manage pinned at the bottom. Hover and focus reveal the full accessible workspace name. Support keyboard switching. Never place project, worktree, or session trees here.

Layer 2 · Navigation / context sidebar

Use 236px within a 220 to 260px range. Show the active workspace name and optional project context, then the only primary destinations: Monitor and Project, both with icon plus label. Destination-specific filters and content sit below.

Layer 3 · Main work area

Render the session list, session grid, project/worktree detail, or active PTY according to destination and selection.

Global top chrome

Command/search, global needs-you queue, and settings span the navigation sidebar and main. Attention remains cross-workspace even when the rail scopes navigation.

Monitor

Filter by Global or Selected workspace, agent, and state. The persistent scope label is never implicit. List/Grid is a layout toggle over one collection, and attention items remain globally reachable. List groups NEEDS YOU, REVIEW, WORKING, and IDLE.

Project

Always scope to the selected workspace. Show a project picker or breadcrumb, compact worktree list, selected worktree detail, its sessions, and New session. An explorer may exist, but only one project's worktrees expand at a time.

Workspace manager

Create, rename, delete, and reorder workspaces; move projects; add projects. Open it from the bottom rail control. It is not a permanent main mode.

Recovered sessions

A global system group outside the strict hierarchy, visible until each session is reassigned or closed.

02

Workspace rail behavior

Persistent context with predictable, accessible controls.

VisibilityPersistent except in Zen mode. Target 52px, with icons or monograms and tooltips but no resting labels.
Active stateUse fill plus a 2px inset, outline, or adjacent marker. Never rely on color alone. Include the workspace initial and full name in its tooltip and accessible label.
State summaryShow a small needs-you dot plus count. Reveal running count only on hover or in the tooltip to avoid badge noise.
SwitchingClicking changes Project scope. It applies workspace scope in Monitor only when the user chose scoped monitoring. Global Monitor remains available.
Active re-clickA re-click could open rename, move projects, and settings. Prefer the bottom Manage control in v1 to avoid ambiguity, and test this choice with users.
CreatePlus opens a small anchored popover with name and optional color or monogram, not a full modal.
OrderingDrag reorder may come later. Use keyboard and menu reorder in v1 if ordering ships.
OverflowScroll vertically and auto-scroll the active workspace into view.
DeletionBlock deletion while a workspace contains projects or live or recovered sessions.
ResponsiveDesktop is primary. Below 760px, turn the rail into a compact horizontal strip above navigation. Validate the native app's minimum width.

Make state transitions predictable.

DestinationMonitor and Project remain the only primary destinations.
LayoutList and Grid are layouts. Grid shares Monitor's scope and filter state.
Active sessionGlobal and alive across workspace changes. If it sits outside the new workspace, keep its PTY visible until workspace-scoped content is selected, with an “in another workspace” breadcrumb.
Project scopeProject always scopes to the selected workspace.

AttentionThe needs-you queue is always global.

Strong convergence

Four of six independently said Workspace should not be a mandatory visible navigation level. Three independently said sessions must remain directly and globally reachable. Treat these as strong signals, not consensus.

Decision applied

The user chose a persistent rail despite earlier advice to hide Workspace for the single-workspace case. The decision still respects those concerns through an automatic default, a narrow quiet rail, no setup gate, and globally reachable sessions. Persona opinions above remain unchanged.

07

Open questions before UI mock

Resolve capability and ownership before drawing states.

What user-visible capability does Workspace own besides grouping?

Settings, scripts, theme, or session defaults are candidates.

Custom icons and colors or generated monograms?

Recommend generated monograms first, with optional color later.

Should clicking the active workspace open a menu?

Recommend no for v1. Use bottom Manage to keep clicks predictable.

Can one project belong to multiple workspaces?

Recommend exactly one in v1.

Is Monitor global by default for everyone or only power users?

Recommend global with a persistent filter label.

What does Project show when no session is active?

Recommend last pinned or selected project, else the first project with activity.

Are List/Grid filters shared?

Recommend yes, with one collection and query state.

What happens when deleting a workspace with live sessions?

Block deletion or require moving projects. Never terminate sessions implicitly.

Outcome / next artifact

After answering workspace capability and membership, build one detailed Figma-like mock covering Monitor List, Monitor Grid, Project, workspace rail default, hover/focus, needs-you count, overflow, add popover, manage menu, switching while another workspace session remains active, Monitor Global versus Selected workspace, empty state, recovered sessions, and create flows.
