grove · sidebar — polish pass

Findings + a proposed revision against src/gui/rows.rs. Goal: make session navigation the obvious thing, drop chrome that earns nothing, and unify the row vocabulary so the sidebar scans top-to-bottom without snags. The current implementation is catalogued at the bottom of this page for reference.

findings

  1. variable row heights. branch chips stack below non-main worktree names, growing the row to 42px while others stay 28px. Vertical rhythm breaks; the eye stutters scanning a list of worktrees. → render branch inline as a mono suffix; every row is 28px.
  2. two grammars for branch. main worktrees show main as subtle inline text; non-main show a chip on a second line. → one rule: inline mono branch when it differs from the folder name; omit entirely when they match (main on a folder named after the project becomes silent).
  3. UPPERCASE project names. Conflicts with the "terminal-native, quiet, fast" voice; shouts in a surface that should whisper. → lowercase, weight 600, same 12pt. Weight carries hierarchy; the surface stays quiet.
  4. ●0 on empty projects. A count of zero is noise; the chevron already signals "expandable." → hide the count when N=0. The signature glyph stays reserved for "something is running here."
  5. bullet vs. dot. The count chip uses • (U+2022). DESIGN.md §5 reserves the single state glyph as ● (U+25CF). → swap.
  6. always-visible project +. Worktree actions hide until hover; the project + floats permanently, competing with the count for the right edge. → hover-reveal, matching the worktree split-start. Discoverability stays high via the inline + new worktree row at the bottom of every expanded project (already in DESIGN.md §11).
  7. double-painted active chain. The cyan rail + bg-hl currently paint both the active worktree and its active session. Two adjacent rails on a 2-row chain reads as one chunky bar, not as "this is the leaf." → rail belongs to the active session only. The ancestor worktree gets bg-hl without the rail. The ancestor project shows a faint 35%-opacity tick on its rail column — present but not insistent.
  8. orphan separator. When a session has no OSC context (terminal rows), the row still renders terminal· with a dangling middot. → drop the separator and the empty ctx span when the title strips to nothing.
  9. "workspace" header. An UPPERCASE label that names what the sidebar already obviously is. → remove the word; the collapse-all glyph carries enough. Add a c kbd hint next to it — keybindings are first-class (PRODUCT.md §1).
  10. smart collapse-all is good, keep it. Single toggle that preserves the active chain on collapse, expands everything on the inverse. Behaviour stays; only the chrome around it gets quieter.
  11. sort affordance. When five or more sessions live across two or three projects, "where did I leave that agent?" becomes the dominant nav question. → add a sort icon in the tree-head opening a 148px dropdown with three options: recent (default — orders sessions by last activity within each worktree), a → z, z → a. Persists per workspace.

rebuilt · two layouts

information-architecture redesign, not atom polish
The clutter is structural. Three nested expand levels (project → worktree → session) means three chevrons, three action surfaces, three rules for hover affordances — repeated for every project the user opens. The polish pass moved atoms; it didn't change that. Two honest positions on what the sidebar is for:

A — activity stream. The sidebar is a session jumper. Projects and worktrees are context about a session, not levels you navigate through. One flat list, grouped by activity. The worktree creation flow moves to a single + new menu in the toolbar.

B — quiet headers. The worktree is real, the project is a label. Project becomes a section header — no chevron, no action row, hover reveals a +. Only worktrees expand. Session indent drops from 48px to 38px. One chevron per chain.

What changed. No tree. The sidebar is one flat list grouped by activity state (running / idle / worktrees with no sessions). Each row reads top-down: agent + label, then a mono subline locating it in project / worktree · branch. Recency lives on the right.

Spawn from the row you're on. Hovering any session reveals a start-split at the right edge (second row, shown open): starts another agent in that session's worktree, the caret picks which agent. You don't go hunting for the worktree in the bottom group — you act on the session already in front of you. The relative time yields to the chips on hover; the × close sits to their right.

Worktrees with no sessions get the same hover affordance from their grouped bottom section, so "start a session here" is one gesture wherever a worktree appears. The toolbar + stays for the cold-start cases: new worktree (project picker), new project.

What changed. Project drops from a clickable row to a small uppercase section label. No project chevron — projects never collapse; their content does. Worktrees own the only chevron in the tree. Sessions indent 38px (was 48), one less depth stop visually.

Active chain. The cyan rail belongs only to the active session. Its ancestor worktree carries a quiet bg-hl fill (no rail). The project header stays at rest — the chain reads from the leaf back, not from the top down.

Empty projects (yobiken) show only a header + hover-revealed +. No ●0, no chevron pointing at nothing.

Affordances. Project + hover-reveals on the section header. + new worktree hover-reveals at the bottom of each expanded project. Session × hover-reveals on the row. Nothing competes for attention until the cursor signals intent.
