## Current implementation boundary

There is **no named-workspace domain or native A1–G8 fixture runner**. Native `Workspace` in `src/views/workspace.rs` is the app view. `Store` in `crates/grove-core/src/storage.rs` owns flat projects and global view/grid preferences. Do not simulate workspaces by renaming projects. Stable workspace IDs, project membership, switch rollback, MRU deletion fallback, and per-workspace restoration are future implementation work.

Rows below identify current seams, not finished parity. Native paths beginning `views/`, `entities/`, or filenames without a crate prefix are relative to `src/`; `grove_core` identifies `crates/grove-core/src`. `new` names a responsibility, not an existing Rust symbol. `adapt` means a seam exists but needs visual/behavior changes; `add` means the key state/domain/composition is missing. Neither means the screenshot or behavior has passed. Component IDs are exact catalog keys; shared shell components are implicit unless central to the frame.

In the approved frames, Project/List view controls live in the sidebar `.side-head`; Grid hides the sidebar and places its controls in the appbar. Do not duplicate the controls globally in both locations. Component specimens show reusable anatomy; the frame determines placement.

## Reconciled reference contracts

B2, B3, B4, B5 and B7 now use the finalized `COMPONENTS.html` inline-action well: embedded Workspace label, editable value, and trailing named icon action. B4 targets that embedded action. B5 disables Close, input and submit and marks both dialog and field busy, with a named progress indicator. B7 retains Platform and names its embedded action Retry create workspace. Anchoring, frame IDs and board captions remain intact; B6 remains the post-create empty state. This resolves the old footer-action discrepancy; matching native captures are still required.

D4 declares `data-path-error-attachment="underBase"` on its frame as fixture metadata. Its path-conflict message stays beneath Base because the form has no path input. Do not invent an extra field.

The [2026-09-05 implementation plan](docs/superpowers/plans/2026-09-05-grove-ui-overhaul.md) supersedes historical centered-modal, paintless-field and universal-hairline styling, including conflicting assumptions in `plan.md` and conformance R2/R12/R20. Historical files remain preserved; applicable keyboard and process behavior remains required. Native conformance assertions migrate with the replacement components, without discrepancy allow-list entries.

## Fixtures and acceptance evidence

Until a native fixture harness exists, supported states can be explored with disposable repositories and shell sessions under an isolated `GROVE_CONFIG_DIR`. Unavailable states stay marked pending. Do not claim visual or behavior coverage from the HTML alone.

Future fixtures should assign stable workspace/project/session IDs; preserve tree expansion, mode and selected/focused session; inject controlled pending/success/error results for storage/Git/spawn; and use deterministic terminal output and activity state. Assertions must cover retained fields, duplicate-submit prevention, rollback, scope, process identity and focus. Pending/error capture must not rely on timing a real operation. The existing `ActivityStore::set_state_for_test` and GPUI modal interaction tests are useful seams, not a running-app fixture interface.

Capture `#frame-ID .screen` at **1280×800 logical app pixels**, excluding the caption/board. Reset reference canvas transform; wait for fonts; remove demonstration cursor/annotations from evidence. Match native content dimensions, zoom 1.0 and finalized light/dark themes; record device scale. Keep native terminal metrics from `src/fonts.rs`/`src/terminal_element.rs`, including measured cell width, height, caret, selection and resize. HTML prose is illustrative terminal content, not a new approval protocol.

Record each frame's fixture recipe, theme/zoom/size/font/scale, reference and native screenshot paths, behavior-test result, visual deviations and acceptance status. Check hover/focus/error states and resize after baseline geometry. Existing `scripts/screenshot-sweep.sh` targets old Linux/Hyprland iced parity and is not an automated macOS frame runner.

Implementation order and exact checks are maintained in [verification.md](.agents/skills/html-to-gpui/references/verification.md). Reference validation checks these 45 rows against `sectionData`; it cannot certify native fidelity.
