Grove product decision

Workspace and session navigation

Scope
Navigation model and workspace switching
Domain
Rust/GPUI desktop app for AI coding sessions
Perspectives
6 independent, project-specific lenses
Decision

Build a session-first workspace “saved desktop” model.

Use one compact workspace switcher in the session sidebar header. Put a prominent New session action and a searchable session dock below it, grouped by Needs you, Working, and Idle / Recent. Show project and worktree identity as session metadata.

Why

This matches the frequent work: moving between sessions and starting new ones. It builds on Grove's existing Sessions rail and launcher while removing repository hierarchy from the routine path.

Risks to watch

  • Project management becomes too hidden
  • Workspace state restoration feels surprising
  • Long session lists lose scanability
  • Migration from global WorkspaceState becomes brittle

Conditions

  • Visible Browse projects action
  • Search in session and project views
  • Clear workspace label during creation
  • Per-workspace state contract
  • Keyboard and mouse parity
  • Purposeful empty state

Out of scope

  • Cross-workspace mixed dashboard
  • Permanent project tree
  • Many-to-many workspace membership
  • Cloud and team concepts

Independent convergence

The daily user, interaction designer, and accessibility reviewer independently reject forcing project hierarchy into the frequent path. Their reasons differ: switching speed, honest hierarchy, and scalability. That convergence is the strongest signal in the room.
