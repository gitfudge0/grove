Terminal toggle & focus-state fixesTest plan for mod+` switching and the eight bad states it must not join.

This change is UI-state plumbing, not data. Nothing new is persisted and no session model changes — all of the risk lives in the interaction of five flags (grid_view, grid_focused, terminal_focused, focused_pane, chrome_visible/grid_view_before_zen) with the focus resolver focused_session() at src/gui/update/pty_input.rs:163, which decides where every keystroke lands.

Blast radius follows from that resolver. The worst case isn't a cosmetic glitch: it's keystrokes delivered to the wrong live agent PTY (audit finding #4), or silently swallowed with no visible target at all (findings #3 and #5). Either can destroy work in a running agent session, so the plan is deliberately regression-heavy rather than feature-heavy.

Three tiers. R-cases reproduce the eight audited bad states, each citing the file:line it was found at, and assert the fixed behavior. U-cases cover the new toggle's decision table once per screen — workspace, grid, zen — plus the matcher and registry row. I-cases cover the palette drill-in, the mod+/ overlay, and the interplay with the two-press kill confirm.

No e2e harness exists for an iced app, so screen-level cases are manual. There is precedent for the rest: unit tests already live in src/gui/update/shortcuts.rs (see the matcher test near line 906), so the chord matching and the decision table are directly unit-testable. Full Grove update-loop states are exercisable via Grove::update message sequences if a test constructor exists that doesn't spawn real PTYs — otherwise the R-tier drops to manual (see gaps).

1.

terminal_focused survives grid entry

The enter branch at layout.rs:189 never calls leave_terminal_tab, and mod.rs:917 checks terminal_focused before grid — so mod+w in grid kills an invisible home terminal. The sidebar highlight lies, and once the last terminal dies mod+w becomes a dead key in grid.

2.

mod+t in grid or zen spawns an invisible terminal

Scope::Global plus an unconditional terminal_focused = true (mod.rs:953-957): the terminal spawns where nothing renders it, keystrokes keep going to the grid tile's agent, and the terminal is orphaned when grid exits.

3.

Zen plus mod+g twice lands on an empty grid

grid_view_before_zen is never cleared by on_toggle_grid_view, so zen exit restores grid_view = true with tile_order already cleared — a blank pane with a dead keyboard (layout.rs:63-71, 225-228).

4.

Worktree teardown with grid open

kill_sessions_for_wt (src/app/teardown.rs:35-96) fixes only active_session; tile_order and grid_focused go stale. Tiles render the wrong sessions, keystrokes reach the wrong agent, and the corrupted order is persisted.

5.

Closing the last home terminal while focused

terminal_focused = true with active_terminal = None is a keyboard black hole, and mod+w resolves to NoOp (sessions.rs:103-115, terminals.rs:66-76).

6.

Two kill confirms armed at once

pending_kill and pending_kill_terminal can be armed simultaneously, and a stale pending_kill survives a focus change — so a later mod+w is a one-press kill and the two-press safety is bypassed (mod.rs:453-460, sessions.rs:96 vs 220-221).

7.

mod+j/k cycles from an invisible session

From a terminal tab, cycling starts at the hidden active_session and lands on an arbitrary session; the in-grid cycle and select variants never call leave_terminal_tab (sessions.rs:344-393).

8.

focused_pane = Panel stale across grid exit

on_toggle_grid_view's exit branch sets active_session without calling reset_focused_pane(), so input targets another worktree's panel or silently falls back while the UI still draws panel focus (pty_input.rs:141-179).

KnownGaps.

!

1. The whole R tier depends on a testable Grove constructor

Every regression case asserts on update-loop state, which means constructing a Grove and driving Grove::update with message sequences — without spawning real PTYs, real worktrees, or a real tmux server. If no such test constructor exists today, R1–R8 all degrade to manual verification, and the Critical case R4 (wrong-agent keystrokes) is exactly the one you least want resting on someone remembering to click through it. This is the single biggest coverage risk in the plan and worth resolving before the fixes land. Confirmed after implementation: no such seam exists — Grove::new() reads the real config and spawns the heartbeat — so the R-cases were fixed in code but remain manually verifiable only, and the seven cases that did land as automated tests all sit on the pure matcher and decision helpers instead.

2.

Worktree-panel terminal focus is deliberately untested here

The wt_terminals panel has its own focus interactions that overlap the same five flags, but the toggle does not touch it by design decision. Those paths are left uncovered on purpose rather than by oversight — if the toggle later grows to include panel terminals, this plan needs a fourth tier, not an amendment.

3.

Visual rendering of the new palette section is not covered

I1 and I2 assert the TERMINALS section exists, filters, and highlights, but nothing here judges whether it looks right — section spacing, dot colors, how it reads against the agent rows across the ~40 derived themes. That is a visual call, settled in mock review, not a pass/fail case.

Out of scope
  • Worktree-panel terminals (wt_terminals) as toggle targets — the chord addresses home terminals only.
  • Dedicated terminal cycling shortcuts (next/previous terminal) — separate chords, separate change.
  • Merging home_terminals into the session list as a unified model — a refactor this feature deliberately does not require.
  • Performance of the toggle (frame time, PTY resize cost) — no measurable risk at the switching frequency a human keyboard produces.
  • The existing semantics of the mod+t chord beyond the R2 visibility fix — unchanged by design decision.
